# 📋 需求单：Goody 管家界面升级（悬浮球 + harness 级对话体验 + 全历史统括）

> 2026-11-11 深夜定案（Agent_20261111234632）· 用户已答两轮需求挖掘 · 确认后开工

**一句话目标**：Goody 从"能用"升级为"好看好用、统括一切、记得一切"——Siri 式贴桌悬浮球唤起、居中卡片聊天窗（DeepSeek 官网级原生渲染）、管家总览驾驶舱、全历史检索突破上下文限制。

**场景**：项目开发 → PopTools 新功能模块（UI 重构 + 检索域扩展）

**交付物**：①贴桌悬浮球（拖动记忆位置/单击展开/聊天时隐没）②全新聊天窗（居中卡片 + 会话侧栏；思考流式折叠、Markdown+代码高亮流式渲染+块复制、消息操作四件套、会话历史侧栏）③管家总览面板（handover 风格驾驶舱：当前任务/待办/今日活动/记忆条目，点击进对话深究）④全历史检索（LLM 工具统一查 monitor 四流+每日记录+聊天史+记忆）

**关键约束**：原生 Qt 自研渲染（安装包零增长）；性能红线六条全适用；域逻辑 ChatSession/LlmClient/PermissionManager 原则不动，仅做必要扩展（reasoning 透传、检索工具注册）

**验收标准**：真机走查——球贴底不挡窗口且拖动记忆；流式渲染打字机粒度无闪烁、代码块一键复制；长对话中问"我上周三干了什么"答案来自检索（答案引用来源）而非编造；ctest 全绿（新增渲染/检索纯逻辑用例）

**AI代决假设**：
- 悬浮球外观：半透明玻璃感圆球 + Goody 图标，跟随系统明暗主题；呼吸光效仅在 Goody 工作时显示
- "无上下文限制" = 检索式实现（磁盘全量 + 按需取用 + 每日记录分层摘要），LLM 窗口物理上限不变；检索用关键词/全文索引，不上本地 embedding 模型（包体纪律）
- 会话自动标题 = 首条用户消息截断，不额外花 API 调用
- 流式渲染防抖 150ms；ChatSession 40 条截断策略保留
- "编辑重发" = 从该消息分支重问，其后消息丢弃（与主流产品一致）

**下游衔接**：直接执行；分三阶段，每阶段真机验收后再进下一阶段
