# 📋 需求单：托盘菜单精简 + F1 卡顿打桩监控（T-069 验收反馈轮）

**一句话目标**：托盘菜单精简到 设置/关于/退出（入口收进设置页）；给 F1 链路加打桩日志，用一段时间后按日志定位偶发卡顿与"菜单弹出时 F1 卡"。

**场景**：项目开发（T-069 验收反馈增量，同一会话延续）

**交付物**：
1. 托盘菜单只剩 设置.../关于/退出；删掉的入口在设置页有等价物
2. F1 全链路打桩日志（probe 目录 jsonl）：热键回调→抓屏→窗口显示分段耗时 + 托盘菜单弹出/关闭标记
3. 用户日常使用数天后回查日志定位

**关键约束**：
- 菜单删除范围（用户拍板）：截图 (F1)、活动监控、Goody 管家、显示桌面日历、调整桌面日历位置和大小、日历设置、停用桌面日历、收纳盒管理、隐藏收纳盒——共 9 项全撤
- 设置页补入口（原菜单功能的等价物）：日历页加「调整桌面日历位置和大小」+「启用桌面日历」总开关（desktopSurface duty 语义）；Goody 页加「打开 Goody 管家」；通用页加收纳盒组（管理对话框 + 显示/隐藏开关）
- 截图 F1 本身不入设置（热键即入口）；活动监控设置页已有开关；日历「显示日历清单」开关已覆盖显隐语义
- 打桩复用 T-068 MainThreadProbe（探针随 v0.5.1 服役中），扩展 mark(tag) 通用打点，全量落盘

**验收标准**：
- 托盘菜单 3 项；设置页能完成全部被删入口的功能
- probe 日志可见完整链：tray_menu_show → f1_hotkey → f1_start → cap_begin → cap_grabbed → cap_shown（含毫秒差）
- 构建 + ctest 绿；用户拉起目测

**AI代决假设**：
1. 「启用桌面日历」开关采用 desktopSurface stop/resume 语义（原「停用桌面日历」菜单项）；设置页既有「显示日历清单」开关维持 hidden 字段语义不变
2. 活动监控托盘项删除后不补状态显示——设置页开关 + 气泡告知已覆盖
3. mark(tag) 上限 31 字符定长（跨线程 POD），全量落盘不设阈值（频率低）
4. 收纳盒显隐开关语义 = 原菜单 toggleShow（任一可见→全隐藏，否则全显示），设置页为双态开关
