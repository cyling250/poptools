# 📋 需求单：UI 现代化改版（Win11 Fluent 风）

**一句话目标**：以 Windows 11 Fluent Design 为基准，对 poptools 全部界面做整体现代化改版，本轮先出设计方案，用户确认后落码。

**场景**：项目开发（接手已有项目，Qt Widgets C++ 桌面工具箱）

**交付物**：
1. 本轮：设计方案文档（现状问题诊断 + 候选开源方案对比 + 设计 token 规范 + 分界面改造清单 + 实施分期计划），呈现于对话并可落盘
2. 下轮（确认后）：按方案落码改版

**关键约束**：
- 风格基准：Win11 Fluent（用户拍板）——云母质感、圆角卡片、Segoe 字体、明暗双主题跟随系统
- 范围：全部界面（设置 / Goody 对话 / 日历 / 收纳盒 / 截图 / 翻译 / OCR / 悬浮球 / 贴图等）
- 技术栈：Qt Widgets + 现有自绘体系，不推倒重写；开源方案 license 传染性必须评估
- 现有纪律沿用：P-022（自定义类 ID 选择器）、P-023（双通道样式钉扎）、AI 不做自主验收（改版效果由用户目测验收）

**验收标准**：
- 方案：给出可直接照做的改造清单（每界面：改什么、用什么 token、预期视觉），开源方案有 license/成熟度结论
- 落码：全部界面视觉统一走新 token 体系，明暗主题切换正常，现有功能不回归

**AI代决假设**：
1. 设计 token 以 ThemeColors.h 为起点扩展（色板保留 #2B6FF2 主色系），补字体/圆角/间距刻度——不另起炉灶
2. 5 份重复 applyTheme 收拢为统一主题应用层，属于方案核心而非可选项
3. 硬编码深色小窗（CalendarSearchForm 等）一并接入新主题体系
4. Fluent 开源组件库若 license（GPL）或 C++ 可用性不适合，则走"QSS + 自绘"自研实现 Fluent 视觉，不引入重依赖
5. 分期实施：第一期主题底座+设置界面，第二期 Goody 对话，第三期其余界面（顺序可调）
