# T-074 M3 真机验收手册（2026-11-22）

> 七项验收走完即 T-074 可结算。AI 收口自证已覆盖协议与文件契约层（见文末附录）；
> 本手册只列**必须真机**的部分。预计 15~20 分钟。

## 前置

1. 启动 `build/Release/PopTools.exe`（若安装了别的实例先退出）。
2. 首次对话前给 sidecar 几秒钟：悬浮球呼吸 = dsh 正在启动，呼吸停止 = 就绪。
   若悬浮球长时间不亮：查 `%LOCALAPPDATA%/PopTools/PopTools/dsh-home` 存在、
   PopTools.ini `[dsh]` 有 api key（本机已有，不许外传）。
3. 对话全部在 dsh 窗口进行（悬浮球单击 / Ctrl+Alt+G 打开）。工具调用会有过程行。

## ① 「我今天干了什么」（activity 工具）

- **操作**：打开 dsh，输入「我今天干了什么」。
- **预期**：agent 调 `poptools_activity_daily` 取数后概述今天的使用情况。
- **判据**：回答里有真实的窗口/键入内容（不是编的）；如果活动监控开着
  （设置里查），必有时间线摘要。注：当前监控总开关为关，回答可能是
  「监控未开启/无数据」——这算通过（工具链路通 + 语义正确），想看完整效果
  先在设置里开活动监控用半小时再问。

## ② 「把今天的日报写一下」（digest 工具 + 日历链路）

- **操作**：对 dsh 说「把今天的日报写一下」。
- **预期**：agent 调 `poptools_write_daily_digest` 落盘 → 桌面日历当天格
  出现摘要链接 → 双击日历面板后可点击 → notepad 弹出日报内容。
- **判据**：四环全通（落盘 → 日历链接 → 可点 → notepad 打开且内容一致）。
  写完可在对话里说「把刚才的日报删掉」清理（agent 用 digest_list 定位后手删，
  或不管它，30 天保留期与日报路径无清理逻辑——留一条测试日报无害，明天
  正式日报会覆盖同日文件）。

## ③ 「把日历的农历关掉」（settings_set + dirty 协议即时生效）

- **操作**：对 dsh 说「把日历的农历显示关掉」。
- **预期**：agent 调 `poptools_calendar_settings_set` → **桌面日历立即**
  不再显示农历（无需重启 PopTools）。
- **判据**：桌面日历农历消失且其他设置不变。**验收完说一句「把日历的农历
  显示打开」恢复**（对话即可，同样即时生效）。

## ④ 「帮我整理桌面文件夹」（box 工具 + 实时重载）

- **操作**：对 dsh 说「帮我看看桌面文件夹怎么整理」。
- **预期**：agent 先调 `poptools_box_catalog_get` 看现状（本机现有 1 盒：
  电力大数据招投标），给出方案；确认后用 `poptools_box_add` 落地。
- **判据**：**收纳盒面板不重启 PopTools 就出现新盒**（M3 的 box.dirty
  实时重载）。如果只是对话出方案没动手，让它「新建一个测试盒」即可验证
  重载；验完对它说「删掉刚才的测试盒」（box_remove，绝不删文件夹本身）。

## ⑤ 截图历史（贴图副本 → OCR 标注 → 检索）

- **操作**：F1 截一张有文字的图 → 贴图（X 键或右键张贴）。贴 2~3 张。
- **预期**：副本自动落
  `%LOCALAPPDATA%/PopTools/PopTools/captures/2026-11/Shot_*.png`；
  CaptureHistoryJob 启动 2 分钟首扫、之后每 15 分钟一轮（每轮最多标注 3 张），
  给未标注图写 `<名>.label.json` 侧车（本地零 token）。
- **判据**：贴图后等 2~17 分钟（首次标注最迟 2 分钟内发生），对 dsh 问
  「最近截了哪些图」/「哪张图里有 XX 文字」——agent 用
  `poptools_capture_history_list` / `capture_history_search` 回答出
  图的内容。等标注期间可以先做其他项。
- **注**：落盘即验（第 2 分钟查目录有副本 = 贴图链路通）；OCR 标注侧车
  与检索已由 AI 自证（附录），真机重点验「真实贴图进来全链不断」。

## ⑥ 「每天 22 点写日报」schedule 定时（dsh 原生）

- **操作**：对 dsh 说「以后每天 22 点把日报写一下」。
- **预期**：dsh 自己建 schedule 任务（这是 dsh 原生定时能力，不经 PopTools）。
- **判据**：dsh 确认任务已建（它的设置/任务页可见）；到点后日报出现且
  日历当天有链接。**验收时不必真等到 22 点**——可以说「每天 22 点」建好
  任务后，再让它把任务改到「5 分钟后」实测一次，验完删掉测试任务。
  22:00 定时若与心跳/睡眠冲突（机器关机/休眠错过），属 dsh 上游行为，
  不算 PopTools 缺陷。

## ⑦ 悬浮球呼吸随 agent 工具调用（心跳协议）

- **操作**：上面任何一项工具调用进行时，看悬浮球。
- **预期**：agent 调工具期间（MCP heartbeat 每 10s）悬浮球呼吸亮起；
  调用停止约 10 秒后回静默。
- **判据**：呼吸的起止与工具调用对得上（例：①取数时亮、回答完 ~10s 停）。

### 发版纪律备注（下次发版必读）

1. `pack_dsh_runtime.py` 产物必须先传 GitHub Release 资产
   `poptools-dsh-runtime.zip`，iss 的 `DshRuntimeUrl` 指向 `v{版本}` 资产，
   漏传 = 安装器下载 404。
2. 版本号三处同步（CMakeLists.txt / PopTools.iss / MainWindow 关于框）。
3. 强杀 PopTools 不会带走 dsh sidecar（node 孤儿进程继续跑，其 mcp-manager
   会 respawn mcp_server）——正常退出无此现象；开发机重启构建前注意清
   node.exe（只杀 `tools/dsh` 那个，别误杀别的 node）。
